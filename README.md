# sheep-helper

一个本地、脱敏优先的《羊了个羊：星球》通关辅助。在本机解析布局、恢复牌面、搜索路线，并提供逐步指引和可选自动点击（含后台模拟点击）。道具和复活由玩家操作并确认；工具不重放或提交游戏请求。

## 当前能力

- 从 HAR 文件读取 JSON 响应，并删除会话凭据、账号标识、签名和 URL 查询参数。
- 从嵌套 JSON 中寻找可能的卡牌数组，归一化为最小棋盘布局。
- 为 `mitmproxy` 生成抓包命令；实际执行前仍需用户自行处理证书信任。默认只捕获地图，恢复加密种子须显式加 `--recover-seed`。
- 用精确规则状态规划路线：遮挡图、按牌型插入的消除栏、移出三张、复活移出和移出区回取均可回放验证。
- 提供手动对局会话层：路线只要偏离即失效，可按当前状态重新规划；不发送鼠标点击。
- Windows 桌面逐步指引：按钮启动抓包、解包并限时求完整路线；手动确认进入目标关卡后对齐准心，按需开启自动点击，或自行点击并手动推进。大世界和每日关卡共用求解与指引流程。

## 架构

```
通用 HAR  →  仅作协议侦察

专用 .map 捕获  →  protobuf 解包  →  已验证四整数种子  →  牌面恢复
                                                           ↓
                                              精确规则模型与求解
                                                           ↓
                                      本地手动建议会话（下一步、校验、重规划）
```

## 使用

若不希望自动点击占用真实鼠标，可勾选“后台模拟点击”，再开启自动点击。先在游戏可见时完成牌面核对及对齐，随后可切换其他窗口或遮挡游戏，但请勿最小化游戏。后台模式通过窗口消息发送点击，并读取游戏窗口本身的画面确认出牌；后台截图失效或点击未确认时会停止，不会回退到移动真实鼠标。部分微信版本可能不接受窗口消息，需要在实际牌局中核验。

移出区回取已支持准心定位和自动点击：手动完成移出道具或广告复活并确认后，重新开启自动点击即可取回移出的牌。程序先识别底部消除栏，再定位其上方三列牌堆的最上层，不假设移出牌与棋盘牌尺寸相同。定位不明确时停止自动点击，保留手动确认入口。已通过真实移出牌截图、缩放截图及点击流程测试；新版自动取回的完整实局仍需核验。

```powershell
python -m pip install -e .
sheep-helper inspect capture.har
sheep-helper export capture.har --candidate 0 --output layout.json
sheep-helper capture-command --process WeChatAppEx.exe
```

## 桌面逐步指引（MVP）

### 双击运行 EXE

日常只使用 `dist\SheepHelper.exe`：它已合并后台模拟点击、移出牌识别及抓包代理修复，保留原来的 20 秒混合求解方式。重新打包固定更新这个文件；旧版会自动归档到 `build\exe-backups`，不会继续在 `dist` 生成多个版本。后台模拟点击仍需勾选启用，游戏窗口请勿最小化。

在这台已配置好抓包环境的 Windows 电脑上，先关闭旧版助手，再双击唯一的 [SheepHelper.exe](dist/SheepHelper.exe)。先按“开始抓包”，等面板显示就绪，再在游戏内开启一局新的大世界或每日关卡；通常不必关闭小程序。如果一直没有收到开局请求，才完全关闭并重新打开小程序重试（已建立的网络连接可能沿用旧代理）。两种模式都会先出现要你自行通过的第一关；程序提前选出第二关地图并求解，但在你按“我已进入第二关”或“我已进入每日第二关”之前不会对齐、标记或点击。确认后才根据当前游戏画面自动对齐。核对准心与牌型无误后，可自行点击并确认每步，或手动开启“自动点击”。道具和复活仍由你完成并确认。20 秒内未找到完整路线会停止本局抓包并提示重开，不会提供部分路线。

“暂停”现在会重置本局，可在抓包等待、求解中或逐步指引的任何时刻使用：它停止本局记录、恢复临时系统代理、清除当前路线和准心，并重新启用“开始抓包”。不会关闭游戏或替你重开关卡；已保存在本地的抓包文件也不会删除。

关闭助手时，代理守护进程独立启动，抓包插件从 `captured-layouts\.capture-runtime` 中加载，不占用单文件 EXE 的临时解包目录，避免退出时出现“Failed to remove temporary directory”警告。抓包运行目录按插件内容分版本保存，供现有监听器继续使用。

自动对齐失败时，牌面已核验的关卡会保留橙色“待校准”准心预览，方便在“校准微调”里调整中心和牌间距。预览状态不会点击或推进路线；点击“应用微调位置”后，手动下一步与可自行开启的自动点击都会恢复。每日关卡若牌面尚未核验，仍不显示可能误导的标记。游戏窗口最小化时无法对齐，先恢复游戏窗口再点“重新自动对齐”。

每日新局若没有 `match_data`，程序按客户端的地图种子算法还原全部牌面；若返回运行时牌局 `match_data`，则解包服务器给出的每张牌及类型，并逐一核对地图坐标。缺少必要的运行时牌面时会隐藏标记并禁用点击；坐标微调不能绕过此检查。含有消除后会变换牌面的特殊砖块时，静态路线不可用，会提示换局。新版首次抓包会重启本项目自身的旧监听器以载入新解包插件；此操作在你进入新局前进行。EXE 仍依赖本机的 `mitmdump`、证书和 Clash 上游代理。若显示“已收到地图，仍在等待本局种子”，可重新进入关卡；`captured-layouts/game-capture-status.json` 仅记录接口路径、响应码与字段名，不保存账号数据。

放在本项目 `dist` 目录时，EXE 使用项目的 `captured-layouts`（与当前抓包代理一致）。移到其他目录时，若 EXE 同目录有 `captured-layouts` 就使用它，否则存到 `%LOCALAPPDATA%\SheepHelper\captured-layouts`。若抓包已完成但面板被关掉，可在一小时内点“载入最近抓包”恢复当前局路线，不必重新开局。高级用法可传入 `--capture-dir`、`--timeout` 或 `--no-start-capture`。

重新打包：

```powershell
python -m pip install -e ".[capture]"
python -m pip install "pyinstaller>=6,<7"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_exe.ps1
```

产物在 `dist\SheepHelper.exe`。重新构建需要 Windows、Python 3.10+；在另一台电脑运行仍需先配置 `mitmdump` 的 PATH、微信抓包和 mitmproxy 证书。

### 从源码运行

在已配置本机 mitmproxy 证书、微信抓包可用的 Windows 环境中，**先启动指引并点击“开始抓包”，再打开新的一局目标关**：

```powershell
sheep-helper guide --timeout 20
```

点击面板“开始抓包”后，指引会启动本机 18888 抓包代理；若端口已有本项目上一会话的监听器，会重启它以载入新版插件。然后暂时把 Windows 系统代理从已配置的 Clash `127.0.0.1:7890` 或 `127.0.0.1:7897` 切到 `127.0.0.1:18888`，让新请求经过抓包器。已打开的小程序可能继续沿用旧连接；先试在游戏内开启新局，若未收到请求再重新打开小程序。地图和种子齐备后立即停止本局记录并恢复原系统代理；等待两分钟仍未抓到、求解失败、关闭助手或助手意外退出时也会恢复。抓包代理进程会保持运行，以便微信已有连接不断线。程序在最长 20 秒内求解，只有完整回放通过才显示标记；超时不等于证明无解。`--no-start-capture` 不自动切换代理，只监听你自行运行的抓包代理。

系统代理支持 Clash `127.0.0.1:7890` 和 `127.0.0.1:7897`，抓包结束后恢复原地址；其他代理配置会拒绝自动切换。电脑重启后先打开助手并点击“开始抓包”，确认显示就绪后再开启新局；如未收到开局请求，再重开小程序。不要在未启动抓包器时手动把系统代理设为 18888，以免游戏显示“网络初始化失败”。

有完整路线且你按“我已进入第二关”后，界面尝试从可见牌的边缘自动对齐，并用四角准心与步骤标签标记下一张；匹配不足时不会启用自动点击，可展开“校准微调”调整位置，再按“应用微调位置”。步骤文案给出区域和牌型名称，如“左上区域准心指向的萝卜”。标记窗口可被鼠标点击穿透。自动点击默认关闭，仅在你开启、游戏在前台、自动对齐已核实、目标坐标位于游戏区域内时逐张点击；每次都等待目标画面变化确认，未确认便停止。程序不再根据牌面颜色推断目标是否可点；因此开启自动点击前请自己核对准心和牌型，若目标已空、被遮住或对齐偏移，立刻暂停并重抓。若你核实这张牌已经点过，可按“我已点此牌”补确认一次。移出道具和广告复活仍需手动完成并确认；移出区回取支持准心定位和自动点击，定位不明确时请手动取回后按“确认已取回此牌”。道具或手动补确认后自动点击保持关闭，须核对下一张准心再重新开启。广告暂时遮住游戏窗口，也不会清除等待复活确认的状态。若点错、换局或画面不符，立刻按“暂停”；不要继续推进。当前每日窗口尺寸已实测通关，换分辨率时首次使用仍请核对准心。

每日关卡曾出现地图种子恢复结果与实见不符，原因是该局带有服务器运行时快照 `match_data`。有快照时以它为准；全新局没有快照时，客户端使用地图种子分配牌面。2026-10-25 新局最初可见的 25 张牌已与种子还原结果逐张核对。对齐算法不依赖某一天固定的底部牌型；匹配不唯一时需手动微调。2026-10-22 曾在实际每日第二关中自动完成 237 张牌；其他日期和分辨率仍需逐局核对首步准心。

牌型名称按游戏更换牌面的 4×4 顺序对应数字 1–16：草丛、萝卜、玉米、木桩、草叉、白菜、毛球、刷子、剪刀、奶瓶、水桶、手套、铃铛、火堆、毛线、稻草。

`--latest` 可载入最近已捕获的局，但仅适用于**当前仍是同一局且尚未偏离路线**；默认只接受点击“开始抓包”后的新种子。进度保存在本局目录，重启时可用 `--resume`，但须先核对游戏实际进度。窗口移动会跟随；窗口缩放后重新尝试自动对齐。当前版本通过鼠标位置与局部画面变化推断普通砖块点击，不直接读取游戏内部点击事件，也不识别胜利画面。

若只想用已保存的完整路线预览标记，不重新抓包或搜索：

```powershell
sheep-helper guide --cards <本局.cards.json> --coverage <本局.coverage.json> --solution <本局.guide-solution.json>
```

## 离线求解


已取得精确 `cards.json` 与 `coverage.json` 后，可在本机生成出牌计划；该命令只读文件，不会连接、点击或提交游戏：

```powershell
sheep-helper solve `
  --cards captured-layouts/64510ca5ca10058da0ca36f5d02fe9bf.cards.json `
  --coverage captured-layouts/64510ca5ca10058da0ca36f5d02fe9bf.coverage.json `
  --output captured-layouts/main.solution.json `
  --time-limit 120
```

默认求解器是启发式 DFS；也可用 `--algorithm beam` 或 `--algorithm mcts`。`--algorithm counts` 是更快的无道具精确状态搜索，`--algorithm batch` 只搜连续三连；后两者不会使用移出或复活。`--algorithm hybrid` 先找无道具前缀，再从该状态搜索道具路线，这是参考 [yangyang-hunter](https://github.com/darkness789/yangyang-hunter) 的两阶段设计。完整规则模型保留：遮挡依赖、按牌型插入的消除栏、三张自动消除、一次“移出三张”的三个临时槽位，以及一次第七格复活后的移出机会；槽中只有 1～2 张牌时也可提前移出。找到的完整路线会由回放器校验。可用 `--no-move-out`、`--no-revive` 或 `--move-out-min-tray 1` 做道具对照。预算内找不到解不等于无解，未求得完整路线时不要按部分路径操作。

`counts` 在没有道具时把同一组剩余牌的不同消除栏顺序合并，因为每种牌在栏中的张数由已取牌数模 3 唯一决定。道具搜索则保留槽位次序；两次道具都用完以后，再合并牌型计数相同的消除栏和互换的临时槽位。历史 225 张牌局的可见 22 张牌通过同图案同类型的核对，但未找到完整路线；后一局 216 张牌已找到完整路线。只有 `solved: true` 且完整回放通过的路线可用于手动操作。

当前局的原版参考算法与替代算法同图对照记录在 [求解算法研究](docs/solver-study.md)。

`capture-command` 只打印命令，不会启动代理。若要使用实时捕获，先安装可选依赖：

```powershell
python -m pip install -e ".[capture]"
```

正式 mitmproxy 附加脚本只保存公开 `.map` 资产和脱敏的游戏开始元数据；请求头、Cookie、token、签名和原始 JSON 响应均不落盘。

## 正式地图采集与解包

通用 `inspect` / `export` 仅用于识别协议形状，不能再作为正式求解地图来源。正式流程只接受 `.map` 资产和对应游戏开始记录恢复出的四整数种子：

```powershell
# 只保存公开地图资产与脱敏游戏开始元数据
sheep-helper capture-command --process WeChatAppEx.exe

# 明确选择后，额外启用一次性本地种子恢复探针
sheep-helper capture-command --process WeChatAppEx.exe --recover-seed

# 一次性生成布局、遮挡图和每张牌的牌面
sheep-helper prepare-session `
  --map captured-layouts/maps/<map-md5>.map `
  --seed-file captured-layouts/seeds/recovered-<timestamp>.json `
  --output-dir captured-layouts/<本局目录>
```

`prepare-session` 会拒绝全零／非法种子、地图编号不匹配和已有不同内容的输出；可加 `--observed visible.json` 核对画面。文件既可用 `{ "tile_id": type }` 做精确类型核对，也可用 `{ "tile_id": "图案名称" }` 检查截图里相同图案是否还原为相同类型、不同图案是否还原为不同类型。后者只验证分组，不独立证明类型编号。相同地图可能在不同局使用不同种子，请为每一局使用独立输出目录。

如果 `.map` 被客户端缓存而没有再次下载，可以使用之前保存的同名 `.map`，但必须与本局种子记录中的 `map_md5` 对上。

`--recover-seed` 不是默认行为。它仅在当前游戏支持的加密种子流程中临时替换本地收到的种子字段，用已知明文推导本次响应的解码流，并在上行转发前恢复原始请求；不会保存 Cookie、token、加密流或任何账号字段。必须在新游戏开始前启动代理；若仅捕获到全零占位种子，不能生成可信牌面。

## 手动建议

在牌面已完整恢复后，可先让 DFS 生成路线，并输出当前可点牌、消除栏、道具使用状态与下一步。该命令不会操控微信窗口：

```powershell
sheep-helper advise `
  --cards captured-layouts/64510ca5ca10058da0ca36f5d02fe9bf.cards.json `
  --coverage captured-layouts/64510ca5ca10058da0ca36f5d02fe9bf.coverage.json `
  --time-limit 120
```

如果返回 `solved: false`，表示当前预算没有找到路线，不表示该局无解。
