前三个压缩／顺序实验使用了之前的合法部分路径作初值，**不包含获得初值的时间**；不能把它们与从零搜索的基线当作同预算的公平胜率对照。状态计数还包含多次重启间的重复状态，吞吐率也不能直接代表解题能力。

冷启动回归还覆盖旧 225 张难图和已知可解的 237 张牌局：该实验搜索各运行 20 秒，分别只到 149/225 和 213/237，均未通关。237 张牌局此前正式混合算法约 4 秒即可完成。因此即使吞吐量提高，当前启发式仍存在明显退步，不能替换正式算法。

上述压缩版本输出的部分路径均通过原 Python 规则引擎回放。217/240 仍是部分路径，**不能用于游戏点击**，也不能证明整个地图无解。

## 可复现实验工具

```powershell
python tools/benchmark_compact_solver.py `
  --cards <本局.cards.json> `
  --coverage <本局.coverage.json> `
  --seconds 20 `
  --output build/compact-cold.json
```

如需研究路径修复，可加一个或多个 `--prefix <先前诊断.json>`。工具将校验牌面、索引及复活标记，并在结果中标注 `warm_started`；带前缀结果不应冒充冷启动成绩。

- `src/sheep_helper/native/CompactSolver.cs`：最终采用的多前缀压缩搜索，之前的实验版本仅保存在本地研究目录。
- `tools/benchmark_compact_solver.py`：按源码散列编译缓存，运行实验并独立回放结果。
- 依赖 Windows 自带 .NET Framework 编译器，无需下载编译器。编译产物只放在忽略的 `build/compact-solver`。
- 原型仅支持最多 256 张牌、16 种牌型，并允许一次移出及一次复活；不支持动态变色牌。工具不能用于其他规则的关卡。
- 随机状态差分测试逐项比对：剩余牌、可点牌、消除栏顺序、三列牌堆顺序及两种道具状态。
- 任何输出仍以 Python 规则引擎为准，只有完整清空棋盘、消除栏和移出区才标记为 `solved`。

原始实验结果保存在 `build/solver-optimization`，汇总为 `verified-summary.json`。该目录不提交真实抓包或编译产物。

## 回归与桌面集成

同预算 20 秒的九份先前缺少路线样本中，原混合搜索找到 1 份，压缩多前缀搜索找到 4 份；十份此前可解的不同地图，压缩搜索全部在约 0.1～0.9 秒解决。这是小样本，不代表对任意种子保证成功。

其中 216 张牌的一个种子原算法约 17 秒找到解而压缩算法未找到，说明两个搜索互有优势。因此正式流程同时运行原算法与新搜索，共用一个总时限，接受首个通过独立回放的完整解，并停止另一边。原算法的 20 秒分组、默认 20 秒时限、原有道具策略继续保留。Windows 后端缺失、损坏或规模超过支持范围时，原算法继续运行。

同预算复测时，这份 216 张样本在某些运行中原算法及并行流程均超时。限时截断、机器负载及重启顺序会改变实际前缀，不能宣称并行方式在每次运行、每份种子上都没有时间回归。

新后端由构建脚本编译并嵌入单文件 EXE，使用持久运行缓存；独立子进程不会占用 `_MEI` 文件。取消、超时、任一算法胜出均回收子进程。后端任何部分路径或伪造完成状态都不会成为游戏路线。

最终 EXE 通过隐藏离线探针直接读取测试牌面，绕过已保存解，从零运行正式并行流程。结果记录在本地 `build/solver-optimization/release-today-result.json`，`packaged=true`、`cold_start=true`，输出动作再次由 Python 回放验证。进程退出后对应 `_MEI000062a02` 目录已删除，后台搜索子进程已结束。唯一发布文件为 `dist/SheepHelper.exe`，旧版归档至忽略的 `build/exe-backups`。

最新完整回归运行共 121 项，其中 120 项通过，仍有一项既有后台点击“鼠标完全静止”断言失败（本次检测到真实鼠标从 `(391,714)` 到 `(377,718)`）；本轮没有放宽该断言，不能声称完整回归全绿。随后新增今天完整路线的双引擎回放测试，与求解器专用测试一并通过。EXE 构建时的启动自检、无抓包启动及退出检查通过。

求解器专用检查包含取消传播、双向胜出后停止对方、原算法回退、非法原生结果拒绝、不支持规模回退，以及真实子进程运行期间取消后进程回收和输入临时文件清理。
