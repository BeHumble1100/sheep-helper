# 历史牌局求解算法对照（2026-10-22）

上一局 225 张牌的完整牌型由 `.map` 与当局种子恢复；当时画面可见的 22 张牌只完成了图案分组一致性核对，不能代替对全部隐藏牌的独立验证。任何 `solved: false` 的部分路径都不可用于实际点击。

## 参考项目的实际策略

[yangyang-hunter](https://github.com/darkness789/yangyang-hunter) 的桌面助手按种子 `(0, 2, 1, 3, 4)` 尝试：先用 [无道具 DFS](https://github.com/darkness789/yangyang-hunter/blob/main/yangyang_hunter/solve.py)（每组最多 150 万状态、30 秒、最多 6 个候选），再从其最深前缀运行 [含道具 DFS](https://github.com/darkness789/yangyang-hunter/blob/main/yangyang_hunter/solve_with_tools.py)（每组最多 200 万状态、40 秒、最多 8 个候选）。它是有界启发式搜索，不是无解证明器。

本项目已按相同数据运行原版代码，并核对了 225 张牌的遮挡关系与一条 188 步部分路径的逐步规则状态。原版实测：

| 随机种子 | 无道具最深牌数 | 含道具最深牌数 | 完整通关 |
| --- | ---: | ---: | --- |
| 0 | 162 | 197 | 否 |
| 2 | 162 | 197 | 否 |
| 1 | 147 | 158 | 否 |
| 3 | 144 | 174 | 否 |
| 4 | 147 | 158 | 否 |

因此直接复制该算法未能解决上一局。仓库也未见明确授权文件；保留算法思想与独立实现，而不整段复制源码。

## 替代算法实测

| 方法 | 限额 | 结果 |
| --- | --- | --- |
| 本项目复刻参考项目无道具优先级 | 150 万状态 | 162 张，与原版一致 |
| 从固定 162 张前缀穷举道具时机和可点牌 | 约 65.7 万等价状态；移出可在 1～6 张时使用，分支上限覆盖全部剩余操作 | 此固定前缀在当前规则模型下不可完成 |
| 多样性无道具束搜索 | 宽度 1000；约 223 万扩展 | 128 张 |
| 多样性无道具束搜索 | 宽度 5000；60 秒、约 849 万扩展 | 77 张 |
| 有限偏差无道具搜索 | 60 秒、约 928 万状态 | 111 张 |
| 全局拓扑顺序退火 | 60 秒 | 最佳无道具容量峰值 12，但仍有溢出 |
| 固定顺序下完整枚举道具调度 | 对两条峰值 12 顺序分别约 8 万和 10 万状态 | 最远 140、144 张，均未通关 |

束搜索与有限偏差搜索目前没有超过原版基线，不应进入正式求解器。拓扑顺序搜索展示了另一种建模方式，但“容量峰值 ≤12”只是两次各移出最多三张的必要条件，不足以保证存在合法的道具调度。

## 后续方向

优先保留精确回放器，继续探索道具状态参与的搜索：对多个不同的合法前缀做约束驱动的邻域搜索，同时记录某一固定前缀已经穷尽、某一搜索只是超时这两种不同结果。考虑使用 CP-SAT 处理局部前缀的遮挡前置约束、槽位容量和三消状态，但在 225 张全局时序与道具槽位上直接建模可能过大，须先在缩小的子问题上基准测试。约束规划与多样性搜索的相关资料：[OR-Tools CP-SAT](https://developers.google.com/optimization/cp)、[Best-First Width Search](https://ojs.aaai.org/index.php/AAAI/article/view/11027)、[优先级约束分类排序的动态规划](https://www.gerad.ca/en/papers/G-2017-82)。

## 新局与多前缀实验（2026-10-22）

新局为 216 张牌、`level_key=100022`、地图 `c18f6c3f109d7d51ac4dd5ee49a2ae4d`。原参考算法及本项目 `hybrid` 均找到完整路线；本项目为 1474050 状态、4.74 秒。两条路线都经过两套规则引擎逐步回放。新局没有取得视觉抽查截图，因此牌面由地图与捕获种子推导，尚未独立核对当前画面。

针对上一局 **verified 种子** 的 225 张牌（不是目录根部同地图的另一种子），参考 [Limited Discrepancy Search 原论文](https://www.ijcai.org/Proceedings/95-1/Papers/080.pdf) 关于启发式早期错误的分析，尝试在无道具 DFS 中采样不同的合法前缀，再分别搜索道具后缀。实验脚本是 `tools/benchmark_diverse_prefixes.py`；正式 `hybrid` 尚未切换。
