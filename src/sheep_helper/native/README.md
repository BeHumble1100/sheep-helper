# 压缩状态搜索

`CompactSolver.cs` 是桌面程序使用的 .NET Framework 搜索子进程。构建时由 Windows 自带的 `csc.exe` 编译并打入唯一的 EXE；用户运行时无需编译。最多支持 256 张普通静态牌、16 种牌型，允许一次移出和一次复活。规模超限或后端不可用时继续原 Python 混合算法。

剩余牌和可点牌各由四个 64 位整数表示。消除栏每张牌使用 9 位身份索引，三列移出区保留各自的后进先出顺序。第七格未消除时触发复活。状态去重保留尚未使用的道具、消除栏和移出区信息；两次道具耗尽后按等价牌型状态合并。

搜索前 90% 时间不断产生无道具前缀：每次最多 147 万状态／2 秒，随后用精确道具模型继续该前缀，最多 203 万状态／2 秒。后续轮次扰动同分动作，避免一直搜索同一深前缀。余下时间尝试回退、修复与不同排序。有限分支和预算意味着搜索不完备，超时不能证明无解。

输入为 `types`（0～15）、`layers`、`blockers` 数组，输出 `solved/actions/states/seconds/best`。动作代码非负数为棋盘索引，`-1` 为移出，`-2/-3/-4` 为回取对应列；复活标记由 Python 按实际溢出重新生成。`traces` 入口仅供规则差分测试。

Python 包装层不信任子进程的完成标志，会逐步回放并核对已取牌数及棋盘、消除栏、移出区全部为空。运行前将子进程复制到持久缓存，避免持有 `_MEI` 文件导致退出清理弹窗；取消、胜出或超时都会回收自己启动的进程。

程序并行运行原混合算法与本搜索，共享用户设置的总时限，采用首个通过回放的完整解。并行会占用额外一个 CPU 核心，具体解题时长受机器负载及限时截断影响。实验与实测见 [优化记录](../../../docs/solver-optimization-2026-11-18.md)。
